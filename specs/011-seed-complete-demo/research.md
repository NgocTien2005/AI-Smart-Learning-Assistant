# Research — 2026-11-08

- Decision: installed Prisma7.10 transaction API, serial execution under a transaction advisory lock and ownership registry. Rationale: no partial rows/race adoption or password-resetting upserts. Alternatives: prefixes alone do not prove ownership; external manifests cannot commit atomically with DB rows. Current prisma.io transaction URL redirects to ORM8 examples, so those APIs are not copied. Verified installed generated class.ts exposes `$transaction(fn,{maxWait,timeout,isolationLevel})`; no upgrade. [Official transaction documentation](https://www.prisma.io/docs/orm/prisma-client/queries/transactions) consulted with this version caveat.
- Decision: existing fs exclusive creation and prebuilt original browser-rendered PDFs. Rationale: retain readable Vietnamese glyphs/text layer and no extra runtime dependency. Existing pdfFixture maps arbitrary glyph codes and is a parser fixture, not suitable visually as a real handout. [Node24 filesystem flags](https://nodejs.org/docs/latest-v24.x/api/fs.html#file-system-flags).
- Decision: explicit dev purpose marker + local daemon/HTTP/container/actual DB checks. Rationale: current default Docker NODE_ENV=production does not identify a deployment; a flag alone or TEST_API_URL alone is insufficient. Reuse acceptance guard principles, forbid local8081.
- Decision: generated per-user access is kept only in memory/internal pipe, shown in dedicated private TTY. Rationale: user forbids credentials in files/chat/evidence. No plaintext access artifact, hardcoded password or reset on rerun.
- Existing faults: old seed creates3users/2courses/4lessons, hashes a hardcoded password then overwrites existing credentials/roles, writes legacy extractedText without source metadata and seeds submitted quiz without selected-answer lifecycle. New namespace avoids mutating those existing records.
