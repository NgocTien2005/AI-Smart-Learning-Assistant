# Research — 2026-11-07

- **Decision**: Google Identity Services official rendered popup button and backend ID-token verification. **Rationale**: Authentication only; public client ID, no client secret or mailbox scopes. **Alternatives**: Server authorization-code flow would add unnecessary secret/access-token lifecycle; automatic email linking/provisioning is explicitly rejected by the user.
  Sources: [setup](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [button](https://developers.google.com/identity/gsi/web/guides/display-button), [JavaScript reference](https://developers.google.com/identity/gsi/web/reference/js-reference).
- **Decision**: Existing jsonwebtoken plus Node crypto, Google's fixed rotating JWKS and bounded cache. **Rationale**: Google permits general-purpose JWT libraries; verify signature/audience/issuer/expiry and use stable `sub`. Add nonce and an HttpOnly browser-binding cookie for custom JS callback POST CSRF/replay defense. **Alternatives**: No tokeninfo production dependency, no unchecked client claims or email-based identity.
  Sources: [server verification](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token), [jsonwebtoken maintained documentation](https://github.com/auth0/node-jsonwebtoken), [Node crypto](https://nodejs.org/api/crypto.html#cryptocreatepublickeykey).
- **Decision**: Nullable unique User.googleSubject; no provider tokens stored. **Rationale**: One provider, one link; preserves existing non-null passwords and all role/course relations. **Alternatives**: General provider table unnecessary for the explicitly single-provider scope.
- **Decision**: Same-origin Vite `/api` proxy to Docker frontend8080 and explicit local CORS override. **Rationale**: Observed backend3000 is internal-only and origin5173 was rejected. **Alternatives**: Exposing DB/backend ports or disabling CORS would broaden access without fixing configuration precisely.
  Source: [Vite server proxy](https://vite.dev/config/server-options.html#server-proxy).
- **Decision**: No actual provider pass until client setup/user-operated Google UI exists. Fixture and isolated DB tests provide independent implementation evidence. No unresolved design research remains.
